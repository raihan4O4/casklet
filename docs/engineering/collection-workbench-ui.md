# Collection workbench UI overhaul

Implemented 2026-10-24. Current design: ../../DESIGN.md. Decision: ../adr/0042-collection-workbench-ui.md. Supersedes resource-atlas navigation placement and visual composition; preserves its functional changes in the initially dirty working tree.

## Experience and implementation

Main navigation is a full-width command header for Casks, Installations, Activity and Settings, with a separate local-storage utility. Independent Cask windows have identity, a four-section horizontal index, scrollable contents and persistent task actions. The shared NavigationRail component retains its public contract and Alt+1 through Alt+4 with modal suppression; its rendered layout is now horizontal.

The library combines identity/creation and real measurements with unified search/view controls, sorting and collection cards or dense rows. Overview leads with actual contents and direct inventory navigation, then storage and dates. Mineral Light and layered charcoal Dark use shared semantic roles, local Inter, restrained 8px panels and configurable cobalt actions. Collection colors identify stable Casks, never ownership or health.

Files & Folders gains local search across saved names, categories and paths. Matching groups reveal rows without fetching contents. Search retains complete category accounting and labels totals when rows are filtered. An action reveals search matches without binding normal manual disclosure state. Inspectors keep identity once, remove nested editor framing and use assigned-category icons. Application intake uses one vertically ranked method list. Cleanup effects include source paths and retain exact-hash review, state-specific transitions and all execution guards.

Creation, batch intake, consent/partial retry, inventory, resource editors, folder inspection, applications, MSI/EXE/elevation/recovery, association, portable ZIP, WinGet, settings, categories, archive, exports, backup, diagnostics, activity/recovery, saved cleanup, confirmations, menus and notifications use shared design roles. No production mocks, new dependencies, schema, IPC, native lifecycle or Rust policy changes. Existing metadata-only opening and capability gates remain.
