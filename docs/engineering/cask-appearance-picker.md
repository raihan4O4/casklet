# Cask appearance picker

Implemented 2026-10-25. Decision: ../adr/0044-cask-icon-and-emoji-picker.md. Extends the shared collection-workbench system and automatic colors from ADR 0043.

## Experience and implementation

New Cask retains name-only creation by default. Its optional collapsed Appearance row opens Icons/Emoji choices, search, 12 named color swatches plus Automatic, a selectable grid and a live preview. There are 24 curated icons and 3,963 fully-qualified Unicode 18.0 emoji across nine categories. Emoji search matches names, categories and pasted glyphs. Results use 96-item pages with a bounded scrolling grid, keeping the picker responsive. The original curated emoji remain first for quick access. Clear restores the default symbol and automatic color. The picker is shared with Cask Settings, where an independent appearance editor uses explicit Cancel/Save. Draft edits do not change existing badges until Save, and Cancel restores focus without modifying preferences.

Creation saves the choice against the stable ID returned by the existing create_cask command before running the caller's open/route callback. Failed backend creation keeps the draft; it cannot write preferences for a guessed ID. No presentation preference is inserted into the core command. Shared CreateCaskForm means first-Cask Explorer intake gains the same optional workflow.

CaskBadge renders the same validated symbol/color in the main card/list library, Cask header, association chooser, Explorer destination chooser, live preview and Settings. Existing automatic colors are preserved. A missing override uses the original collection symbol; Automatic resolves the existing saved base color. Local override records pair symbol and color in one preference value. Malformed/unsupported values fall back safely. Save failure reports session-only presentation. Tauri events update open windows and storage events cover browser-profile updates.

The picker uses existing local Lucide modules and Unicode emojis, with no new package, network asset, image generator, schema, contract or Rust policy changes. The supplied reference informs the compact controls rather than replacing the current palette or interface language. Icons use readable neutral theme ink; selected controls use existing accent/focus roles. Symbols are decorative beside real Cask names. Search Enter is prevented from submitting the outer creation form; Escape collapses the focused picker and returns to its trigger. Dialog focus continues to use the existing native modal behavior. Sticky commit actions keep Create/Save reachable while scrolling expanded choices.

## Limits

Appearance is saved per local desktop profile, like the existing theme/accent preferences, and is not part of portable exports or SQLite backups. Emoji shapes follow the Windows/system emoji font. Native Explorer shell-menu branding remains unchanged. No installer rebuild, hosted CI, full screen-reader/physical-picker acceptance or public-release clearance is claimed. Existing project release/security gates remain open. Unrelated dirty worktree changes are preserved.

## Bounded Settings editor and white background (2026-10-26)

The previous Settings commit row used sticky positioning over the appearance picker. As the outer workspace scrolled, symbol content could remain visible below Save/Cancel, making the editor appear broken. Settings now uses two grid rows: a bounded scrolling picker and a separate normal-flow commit row. Picker content is clipped to its scroll viewport and cannot appear beneath the actions. Creation's existing dialog actions are unchanged.

White replaces the magenta/Berry swatch while retaining 12 choices plus Automatic. The retired #e040fb remains valid for saved base colors and appearance overrides, and appears as Saved color where needed. White has a bordered circular swatch for visibility in Light. Shared CaskBadge renders an explicit #ffffff background and dark glyph when white is selected, including Dark mode; emojis retain their native colors. Existing saved choices, stable IDs, Save/Cancel semantics and local preference scope remain. No schema, core command or destructive-policy change.

Validation: production build, zero-error/warning Svelte check, ESLint and 125 frontend tests pass. Added tests verify white draft preview/save, persistence across reload and retired-magenta compatibility. `scripts/appearance-picker-audit.mjs` checks 36 combinations of scroll position, symbol mode, theme and 390/560/1024px width, ensuring symbols never overlap or peek below actions. It also verifies actual white preview/workspace surfaces, saved emoji/color pairs, reload and zero axe/console findings. Evidence: `.jury/appearance-footer-white`. An isolated real Windows WebView reproduces the Settings emoji/category scroll in Light/Dark and saves a white emoji badge successfully; captures and result are in `native`. This serves the production frontend to the existing debug host, not an installed-release update.

## Default-yellow, Windows-compatible selection (2026-10-26)

The full Unicode catalog exposed skin-tone repetitions, newly standardized sequences that the host font could not render, and regional flags that Windows displayed as country-code letters. The selectable catalog is now a generated 1,544-entry subset: Emoji version 13.0 or earlier, no Fitzpatrick modifiers, no regional-indicator/tag flags and no standalone Component entries. This keeps default yellow people/hands, the existing quick-access choices, search, 96-item pagination and all nine categories. Flags now contains eight symbol flags, visually confirmed as real glyphs in the native Windows WebView. Newer choices are deliberately excluded rather than relying on unreliable runtime missing-glyph heuristics.

`generate-emoji-catalog.py` generates `emoji-picker-data.json` alongside the full catalog using explicit version/code-point rules. The complete 3,963-entry catalog remains the saved-value validation source. Previously saved flags, tones and joined sequences still round-trip; they are not newly offered in the picker and use a Saved emoji label when absent from its selection list. No font/network/package dependency, image replacement, core command or schema change. White backgrounds and the separate action row remain.

## Unified Cask Settings save/reset (2026-10-26)

The explicit follow-up replaces appearance-only Cancel/Save controls with the existing workspace Reset changes / Save changes footer. CaskAppearanceSettings is now a controlled draft editor; Workspace owns its value and open state. Appearance changes participate in the same dirty state as name, description and archive. Reset restores all fields from current saved state and closes the picker. Save closes the picker only after a successful commit. The appearance preview is local to Settings until Save; other badges/windows continue showing persisted choices. Picker controls disable while saving.

Appearance-only saves call the existing preference writer without an unnecessary revisioned update_cask command. Combined changes first await the metadata update, then save the appearance; a metadata failure leaves both drafts pending and does not persist appearance. Local storage failures retain the existing session-only warning. The saved-appearance baseline follows cross-window changes: pristine drafts refresh automatically, dirty drafts remain intact, and Reset uses the latest saved choice. Metadata drafts initialize immediately after loading Cask identity, before async content refresh, avoiding an initialization race that could overwrite early edits. No schema, core command, lifecycle or cleanup-policy change.

The picker remains bounded/scrolled inside the workspace; the duplicate action row and its unused styles are removed. The global workspace footer owns the single commit/reset pair and stays outside the scrolling content. Creation retains its existing optional appearance workflow.

Validation: production build, type check, ESLint and all 128 frontend tests pass. Integration tests cover appearance-only save/reset, no redundant metadata command, combined-save failure/retry and Reset after a remote appearance change. The 36-case browser matrix checks global footer separation, no local appearance action buttons, appearance-only dirty state/reset, white emoji save/reload, both themes, three widths and accessibility. Isolated real Windows WebView verifies global footer Reset/Save against a real QA Cask and white emoji badge in Light/Dark. Captures/results: `.jury/appearance-settings-footer`, including `native`. No installed release is replaced.
